# AuraGram — запуск с нуля, шаг за шагом

Нужно: аккаунты Google и GitHub, Node.js 20+. Java 11+ нужна только для проверки правил безопасности (шаг 2).

## 1. Firebase (проект `auragram-enterprise` или ваш)
1. [console.firebase.google.com](https://console.firebase.google.com) → ваш проект.
2. **Authentication → Sign-in method → Google → Включить.**
3. **Authentication → Settings → Authorized domains → Add domain:** `ВАШ_ЛОГИН.github.io`.
4. **Firestore Database → Create database** (режим production, ближайший регион).
5. **Storage → Get started.** В новых проектах для Storage может понадобиться тариф Blaze (бесплатная квота остаётся, нужна привязка карты).
6. Если проект ваш, а не `auragram-enterprise`: **Project settings → General → Your apps → Web app** — скопируйте конфиг в `src/services/firebase.ts` (все поля, кроме `apiKey`, он берёт из кода).

## 2. Правила безопасности (обязательно до публичного запуска)
```bash
npm install
npm install -g firebase-tools
firebase login
firebase use --add            # выберите проект
npm run test:rules            # 11 тестов; нужна Java. Должны пройти все
firebase deploy --only firestore:rules,storage
```
Без Java: вставьте `firebase/firestore.rules` в **Firestore → Rules**, `firebase/storage.rules` в **Storage → Rules**, нажмите Publish. Тогда обязательно проверьте руками шаг 7.

## 3. Ключи
| Что | Где взять | Переменная |
|---|---|---|
| Web API key | Project settings → General → Web app → `apiKey` | `VITE_FIREBASE_API_KEY` |
| VAPID key (push) | Project settings → Cloud Messaging → Web Push certificates → **Generate key pair** | `VITE_FIREBASE_VAPID_KEY` |
| ImgBB | [api.imgbb.com](https://api.imgbb.com) → новый ключ. **Старый ключ из истории git удалите.** | `VITE_IMGBB_API_KEY` |
| Адрес push-сервера | из шага 4 | `VITE_PUSH_URL` |

Там же, в Cloud Messaging, убедитесь, что **Firebase Cloud Messaging API (V1)** включён.

## 4. Push через Google Apps Script
1. [script.google.com](https://script.google.com) → **Новый проект**.
2. Вставьте содержимое `apps-script/Code.gs`. **Project Settings → Show "appsscript.json" manifest file**, замените его содержимым `apps-script/appsscript.json`.
3. **Firebase → Project settings → Service accounts → Generate new private key** → скачается JSON.
4. В Apps Script: **Project Settings → Script properties → Add** три свойства:
   - `SERVICE_ACCOUNT_JSON` = весь текст скачанного JSON
   - `WEB_API_KEY` = ваш Web API key
   - `APP_URL` = `https://ВАШ_ЛОГИН.github.io/auragram/` (со слэшем на конце)
5. **Deploy → New deployment → Web app:** Execute as **Me**, Who has access **Anyone** → Deploy → разрешите доступы → скопируйте URL, оканчивающийся на `/exec`. Это `VITE_PUSH_URL`.
6. Никому не показывайте проект Apps Script и JSON-ключ: он даёт доступ к вашей базе.

## 5. Публикация на GitHub Pages
1. Распакуйте архив поверх репозитория (или `git am` патч), закоммитьте.
2. Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**, добавьте четыре секрета: `VITE_FIREBASE_API_KEY`, `VITE_IMGBB_API_KEY`, `VITE_FIREBASE_VAPID_KEY`, `VITE_PUSH_URL`.
3. **Settings → Pages → Source: GitHub Actions.**
4. `git push` в `main`. Вкладка **Actions** покажет сборку, сайт появится на `https://ВАШ_ЛОГИН.github.io/auragram/`.

## 6. Локальный запуск
Создайте `.env.local`:
```
VITE_FIREBASE_API_KEY=...
VITE_IMGBB_API_KEY=...
VITE_FIREBASE_VAPID_KEY=...
VITE_PUSH_URL=...
```
`npm run dev` → откройте `http://localhost:5173/auragram/`. Для входа добавьте `localhost` в Authorized domains.

## 7. Проверка после запуска
1. Войдите с двух аккаунтов (второй в окне инкогнито).
2. Первый находит второго через поиск, пишет: текст, фото, голосовое, файл.
3. Второй ставит реакцию, пересылает сообщение, ищет по чату.
4. Если что-то не отправляется, откройте консоль браузера (F12): `permission-denied` = правила, `storage/unauthorized` = Storage Rules.
5. Push: в **Настройки → Push** нажмите «Включить», закройте вкладку, отправьте сообщение со второго аккаунта.
6. iPhone: push работает только если открыть сайт в Safari → «Поделиться» → «На экран Домой» (iOS 16.4+).

## Ограничения этой версии
- Сообщения не шифруются end-to-end (хранятся в Firestore открытым текстом, защищены правилами).
- Группы, каналы, истории и лента ещё не реализованы.
- Apps Script не подходит для высокой нагрузки (квоты UrlFetch), для тысяч пользователей перейдите на Cloud Functions.
